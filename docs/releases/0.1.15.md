# omp-superagent 0.1.15

- In a bound topic, the authenticated owner can change a lane’s assignment directly. The lane keeps its workspace and the conditions the owner did not change; it does not ask HEAD to approve the new scope. Pauses and native approvals still apply.
- A late original message cannot override a newer instruction in the same topic. On upgrade, retired scope-review cards cannot authorize new work, and uncertain deliveries are not replayed.
- After `/restart` interrupts an active HEAD goal, the replacement can continue that same goal on its original conversation. It does not replay the interrupted prompt or move its approvals to the conversation that requested the restart.
- Discord links joined HEAD replies to their original messages. The optional `remoteMemorySync` setting lets HEAD pull eligible project facts from an idle paired SSH lane; it is off by default.
- The Gateway adapters now share native dialog validation, and Gateway and Host share RPC chunk limits. The test suite reuses its loopback operator across workers, and CI caches Rust dependencies without skipping tests or reusing tagged package builds.

**Before upgrading**, follow the [upgrade procedure](https://github.com/dbc-hbin/omp-superagent/blob/v0.1.15/docs/OPERATIONS.en.md#update-an-existing-installation) ([한국어](https://github.com/dbc-hbin/omp-superagent/blob/v0.1.15/docs/OPERATIONS.md#기존-설치-업데이트)). Use the old installation to stop affected resident lanes and Gateway/HEAD and verify their exits. `stop main` alone does not stop independent lanes. Keep the original config and journals, install `omp-superagent@0.1.15`, and restart only previously running Gateways.

The `v0.1.14` tag did not publish a package: native restart and bound-topic steering checks failed before publication.
