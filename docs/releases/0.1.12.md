# omp-superagent 0.1.12

**Stop and verify before upgrading.** Follow the [upgrade procedure](https://github.com/dbc-hbin/omp-superagent/blob/v0.1.12/docs/OPERATIONS.en.md#update-an-existing-installation) ([한국어](https://github.com/dbc-hbin/omp-superagent/blob/v0.1.12/docs/OPERATIONS.md#기존-설치-업데이트)) while the original installation is intact. Stop affected resident lanes and the Gateway/HEAD, and verify their exits before replacing files. `stop main` alone does not stop independent lanes. A replacement helper cannot certify a 0.1.10 owner's exit after the fact.

- Local lane shutdown checks the configured socket and the live session, PID and journal before sending a single stop on that same connection. A copied state directory or stale lane record no longer authorizes stopping another Host.
- The packaged upgrade tools capture and recheck live ownership, handle large protocol-v2 state responses, and confirm process exit against a fresh receipt and the original journal file.
- The package upgrade check runs the real npm installation hooks, resumes the same HEAD journal, and checks that the predecessor's observations survive the upgrade.

After confirming shutdown, install `omp-superagent@0.1.12` with `bun add --global --trust` or `npm install --global`. Keep the original config and journals. Use the upgraded CLI to start only Gateways that were running before maintenance.
