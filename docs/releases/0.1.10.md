# omp-superagent 0.1.10

- **Optional KakaoTalk adapter.** Gateway can receive and reply in an owner's one-to-one chat through an operator-run loopback bridge. Superagent does not sign in to Kakao or ship a live Kakao client. See the [bridge protocol and limitations](https://github.com/dbc-hbin/omp-superagent/blob/v0.1.10/docs/kakao-bridge-protocol.md) before enabling it (#56).
- **Shared reply style for HEAD and lanes.** Tell HEAD how to answer future requests. The saved style applies to new conversational replies and survives restart, but does not change tools, approvals, or workflows. Ordinary messages in a bound work thread still go to its lane (#57, #58).
- **Safer recovery after interruptions.** HEAD retries interrupted reads of native completion records. The Host owner retries ownership observation if descendants change, and an exited lane Host no longer holds its slot. A fresh `/restart` can retry a failed checkpoint when no stop was sent (#59, #60, #61, #62).
- **Shorter READMEs and a complete English operations guide.** The [Korean guide](https://github.com/dbc-hbin/omp-superagent/blob/v0.1.10/docs/OPERATIONS.md) remains available.

## Install or upgrade

```sh
bun add --global --trust omp-superagent@0.1.10
omp-sa --help
```

Alternatively, use `npm install --global omp-superagent@0.1.10` with Bun 1.4.4 or later on `PATH`. Install OMP separately; CI uses stock OMP 19.1.1. Installing does not restart a running Gateway.
